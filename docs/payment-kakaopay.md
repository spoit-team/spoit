# 참가비 결제 (카카오페이 단건 결제, 테스트 결제)

참가비가 있는 매치는 신청할 때 카카오페이로 결제하고, 결제가 승인되면 신청이 `확정 대기`로 접수됩니다. 지금은 **테스트 가맹점(TC0ONETIME)**으로만 운영하므로 실제 돈은 청구되지 않습니다.

## 정책

| 상황 | 처리 |
| --- | --- |
| 개인 신청 | 1인 참가비 결제 |
| 팀 신청 | 대표가 `1인 참가비 × 인원`을 한 번에 결제 (예: 9,000원 × 5명 = 45,000원) |
| 본인·대표 취소 (경기 시작 전) | 전액 환불. 취소 수수료 없음 |
| 팀원 일부 취소 | 취소 인원만큼 대표 결제에서 부분 취소 (예: 2명 → 18,000원) |
| 시설 관리자 반려 | 그 1명분 환불 (팀 신청이면 대표 결제에서 부분 취소) |
| 매칭방 취소, 경기 자동 취소 | 대기·확정 결제 신청 전액 환불 |
| 경기 시작까지 확정되지 않은 결제 신청 | 자동 반려 + 전액 환불 |
| 참가비 0원 매치 | 결제 없이 기존처럼 바로 접수 |

신청자가 있는 매칭방은 참가비를 바꿀 수 없습니다(결제 금액과 어긋나지 않게).

## 흐름

```
신청 내용(STEP 1) → 결제(STEP 2) → 신청 완료(STEP 3)

1. POST /matches/{id}/apply/payment/prepare
     서버가 정원·중복·시간 겹침을 확인하고 금액을 계산 → 카카오페이 결제 준비(ready) → payment(READY, tid 저장)
     → 카카오페이 결제 페이지로 이동 (PC·모바일 같은 방식)
2. 사용자가 카카오페이에서 결제
3. GET /matches/{id}/apply/payment/approve?paymentId=…&pg_token=…   (카카오페이가 돌려보냄)
     서버가 매칭방을 잠그고 정원 등을 다시 확인 → 카카오페이 최종 승인(approve) → 신청 생성 → payment(PAID)
   취소·실패하면 /cancel, /fail 로 돌아와 신청 화면에 안내
```

- 금액은 항상 서버가 정합니다. 브라우저는 금액을 보내지 않습니다.
- **최종 승인 전에는 돈이 빠져나가지 않습니다.** 결제하는 사이 자리가 차면 승인하지 않고 "결제는 진행되지 않았습니다"로 안내합니다. 승인은 됐는데 그 직후 신청 저장이 실패한 드문 경우만 바로 전액 취소합니다.
- 그래서 웹훅·점검 스케줄러가 필요 없습니다. 결제 페이지에서 그냥 창을 닫으면 승인이 안 된 채로 끝나 돈이 나가지 않습니다(주문은 `READY`로 남아도 무해합니다).

## 환불 (즉시 환불)

- 취소·반려·매칭방 취소·자동 취소 모두 **처리하는 그 자리에서 카카오페이 결제 취소 API를 호출**합니다.
- **취소 API가 실패하면 신청 취소·반려도 하지 않고** "환불 요청에 실패했습니다. 잠시 후 다시 시도해 주세요."를 보여 줍니다. 경기 시작 때 자동 처리는 실패하면 다음 1분 실행에서 다시 시도합니다.
- 같은 금액을 두 번 취소하지 않도록, 취소 전에 카카오페이 주문을 조회해 누적 취소 금액이 DB 기록과 맞는지 확인합니다. 앞선 시도가 카카오페이에서는 취소됐는데 DB가 되돌려졌다면 다시 취소하지 않고 기록만 맞춥니다.

## 로컬에서 테스트 결제 켜기

1. [카카오페이 개발자센터](https://developers.kakaopay.com)에 로그인하고 애플리케이션을 만듭니다.
2. **내 애플리케이션 → 앱 키**에서 **Secret key(dev)**를 복사합니다.
3. OS/IDE 환경 변수로 설정합니다. 값은 커밋하지 않습니다.

| 환경 변수 | 비고 |
| --- | --- |
| `KAKAOPAY_SECRET_KEY` | 필수. Secret key(dev). 없으면 유료 매치의 결제 버튼이 비활성화됨 |
| `KAKAOPAY_CID` | 선택. 기본 `TC0ONETIME` (테스트 가맹점) |
| `KAKAOPAY_TEST_MODE` | 선택. 기본 `true`. 신청 화면에 "실제 금액이 청구되지 않습니다" 안내 |

4. `db/migrations/20261108-payment.sql`을 로컬 DB에 적용합니다([마이그레이션 안내](../db/migrations/README.md)).
5. 앱을 다시 띄우고, 참가비가 있는 매칭방에서 신청하면 STEP 2에서 카카오페이로 결제할 수 있습니다.

## 운영 서버 반영 (팀장)

1. RDS에 `db/migrations/20261108-payment.sql` 적용
2. EC2의 `/home/ec2-user/spoit/.env`에 `KAKAOPAY_SECRET_KEY` 추가

카카오페이가 결제 뒤 돌려보내는 주소는 요청한 서버 주소를 그대로 쓰므로 도메인 설정은 따로 없습니다. 실제 결제로 바꾸려면 사업자 등록과 카카오페이 가맹 계약이 필요하고, 그때 발급받은 CID와 운영 Secret key로 바꾸고 `KAKAOPAY_TEST_MODE=false`로 둡니다.

## 확인할 곳

| 무엇 | 어디 |
| --- | --- |
| 결제·환불 금액 (결제한 회원만) | 마이페이지 → 신청 내역 |
| 신청 행별 결제 상태 (무료·결제 완료·환불 완료) | 시설 관리 → 매치 운영 상세 → 참가 신청 내역의 `결제` 열 |
| 결제하지 못하고 끝난 사유 | `payment.fail_reason` |
